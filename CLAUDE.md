# Робочі правила для цього репозиторію

Контекст і мета — у `README.md`. Як усе влаштоване й чому саме так —
в `ARCHITECTURE.md`, там же каталог особливостей заліза. Перелік завдань —
у GitHub Issues.

Читати `ARCHITECTURE.md` першим: без нього легко «виправити» те, що відтворено
навмисно.

Коротко: це емулятор ігрової консолі Лілка в браузері. Головна вимога — **збіг
із залізом**, а не «щоб працювало». Усе, що суперечить цій вимозі, є помилкою,
навіть якщо виглядає розумніше.

## Перед тим як щось міняти

1. Прочитати розділ «Особливості заліза, відтворені навмисно» в
   `ARCHITECTURE.md`. Там перелічені місця, які виглядають як помилки, але є
   навмисними.
2. Запустити `npm run check` — усі 112 перевірок мають бути зелені **до** правок.
   Інакше незрозуміло, що зламано.

## Головні заборони

**Не «виправляти» особливості прошивки.** Білі кути в обернених спрайтах,
`ry` замість `rx` у `writeEllipseHelper`, відсутність `math.huge` — усе це
відтворено навмисно і закріплено тестами. Якщо тест раптом заважає, це не привід
його змінювати: спершу треба зрозуміти, що саме він захищає.

**Не писати числа про залізо руками.** Розміри екрана, піни, значення констант,
таблиці синусів, дані шрифтів беруться зі `src/generated/`, а туди потрапляють
зі скриптів `gen-*`, які читають код прошивки. Файли в `src/generated/`
редагувати вручну не можна.

**Не використовувати Canvas 2D API для малювання.** `ctx.arc()`, `ctx.lineTo()`,
`ctx.fillRect()` згладжують краї й дають інші пікселі. Малювати лише через
`Framebuffer`.

**Не покладатися на `Math.floor` там, де в C стоїть приведення до `int`.** C
відкидає дріб у бік нуля, тобто `Math.trunc`.

**Не використовувати `localStorage`/`sessionStorage` у коді емулятора.** Для
стану програми — тільки пам'ять; сховище браузера з'явиться разом із
віртуальною файловою системою і матиме власний шар.

## Пріоритет джерел

1. Документація `/latest/` на docs.lilka.dev
2. Активний код прошивки: `lilka-dev/keira`, `lilka-dev/sdk`
3. Офіційні приклади `lilka-dev/examples`

Коли документація й код розходяться — **вірити коду**, відтворювати код і
записати розбіжність, щоб її можна було надіслати команді прошивки.

## Порядок роботи над новою прив'язкою API

1. Знайти реалізацію в прошивці: `lilka-dev/keira` →
   `src/apps/lua/lualilka_*.cpp`, `lilka-dev/sdk` →
   `lib/lilka/src/lilka/*.cpp`.
2. Прочитати її **повністю**, не за назвою функції. Особливо звернути увагу на:
   - типи проміжних змінних (`float` проти `double`);
   - чим саме пушиться результат — `lua_pushnumber` (дробове) чи
     `lua_pushinteger` (ціле);
   - порядок аргументів і те, чи приймається таблиця замість переліку.
3. Реалізувати в `src/runtime/bindings.ts`, позначивши через `impl('назва', …)`
   — інакше функція не потрапить у звіт покриття.
4. Якщо потрібна поведінка, яку JS не виражає (тип числа, форматування рядка) —
   робити це в `src/runtime/prelude.lua.ts`, на боці Lua.
5. Додати перевірку в `scripts/check-runtime.mts`.
6. Оновити звіт: `npm run gen:coverage`.

## Стиль

- Коментарі, повідомлення про помилки й тексти інтерфейсу — **українською**.
- Без займенників другої особи (ти, тобі, твій). Замість «щоб ти не писав
  конфіги» — «щоб не писати конфіги».
- Коментар пояснює **чому**, а не **що**. «Тут `Math.trunc`, бо C відкидає дріб
  у бік нуля» — корисно. «Обрізаємо число» — ні.
- Кожне місце, де відтворено особливість прошивки, має нести коментар із
  посиланням на функцію первотвору.
- TypeScript зі `strict`. Параметри-властивості в конструкторі
  (`constructor(private x: T)`) **не використовувати**: скрипти виконуються через
  `node --experimental-strip-types`, який їх не підтримує.
- Відносні імпорти — з розширенням `.ts`, інакше скрипти під Node не
  запустяться.

## Як перевіряти зроблене

```bash
npm run check      # 112 перевірок: геометрія, шрифти, растр, файли, рантайм
npm run build      # tsc --noEmit + vite build
```

Рантайм Lua навмисно не залежить від Web Worker, тому `scripts/check-runtime.mts`
ганяє його прямо під Node. Нову поведінку рантайму треба перевіряти там, а не
вручну в браузері.

Для візуальної перевірки малювання:

```bash
npm run render:testcard              # testcard.png — геометрія і текст
npm run render:testcard out.png images   # зображення і перетворення
```

## Чого бракує найбільше

Подробиці — в GitHub Issues. Стисло: віджети `alertUI`/`keyboardUI`/
`progressUI`, підсвітка синтаксису, рантайм mJS, Blockly, запуск через USB.

Окремо: жодна тест-карта досі не звірялася зі справжнім залізом. Доки цього не
зроблено, слова «збігається з залізом» спираються тільки на читання коду.
